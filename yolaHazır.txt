2. MEVCUT KODLARIN DETAYLI İNCELEMESİ, EKSİKLER VE DÜZELTİLECEK YERLER
--------------------------------------------------------------------------------

A. VERİTABANI KATMANI (`server/database.js`):
   1. [KRİTİK PERFORMANS EKSİĞİ] SQLite Varsayılan Modda Çalışıyor:
      - Mevcut `database.js` dosyasında SQLite varsayılan "DELETE" journal modunda çalışmaktadır. Her yazma işleminde veritabanı dosyası kilitlenmekte ve disk I/O darboğazına sebep olmaktadır.
      - Çözüm: `PRAGMA journal_mode = WAL;` ve `PRAGMA synchronous = NORMAL;` aktif edilmelidir.
   2. [KRİTİK RAM OPTİMİZASYONU EKSİĞİ]
      - `PRAGMA temp_store = MEMORY;`, `PRAGMA mmap_size = 268435456;` (256 MB) ve `PRAGMA cache_size = -64000;` (64 MB) eksiktir. Veritabanı RAM yerine diski boğmaktadır.
   3. [ÇÖKME RİSKİ] Eşzamanlı Yazma Kilitlenmesi (Busy Timeout):
      - Eşzamanlı isteklerde `SQLITE_BUSY` hatası alınmaması için `db.configure("busyTimeout", 3000);` eksiktir.
   4. [KRİTİK PERFORMANS AÇIĞI] Veritabanı İndekslerinin (Index) Bulunmaması:
      - `ilanTablo` üzerinde `durum`, `bolgeId`, `hayvanTuru`, `kullaniciId` kolonlarında indeks yoktur. Yüzlerce ilan içinde filtreleme yaparken veritabanı her seferinde "Full Table Scan" yapmaktadır.
      - `talipTablo` üzerinde `ilanId`, `talipId`, `durum`, `bolgeId` kolonlarında indeks yoktur.
      - Çözüm: Tablolar oluşturulurken veya kurulurken ilgili alanlara `CREATE INDEX IF NOT EXISTS` tanımlanmalıdır.
   5. [VERİ BÜTÜNLÜĞÜ AÇIĞI] Atomik İşlemlerin (Transaction) Kullanılmaması:
      - İlan verme, başvuru yapma ve mesaj gönderme işlemlerinde `yayinHakki` düşürme ile ilan/başvuru ekleme işlemleri ayrı sorgularla yapılmaktadır. İşlem ortasında çökme yaşanırsa bakiye düşüp kayıt atılamayabilir.
      - Çözüm: `BEGIN TRANSACTION`, `COMMIT` ve `ROLLBACK` kullanılmalıdır.

B. BACKEND SUNUCU KATMANI (`server/server.js`):
   1. [KRİTİK GÜVENLİK VE YÜK EKSİĞİ] Fail-Fast ve Event Loop İzleyici Yokluğu:
      - Yük altında (%75 ve %80) sunucuyu çökmekten koruyacak `perf_hooks` (monitorEventLoopDelay) mekanizması `server.js` içine entegre edilmemiştir.
   2. [KRİTİK GÜVENLİK EKSİĞİ] Ceza Puanlama ve Otomatik Ban Mekanizması Yokluğu:
      - Bot taramaları (404), bozuk JSON (400) ve yetkisiz erişim (401/403) denemelerine karşı IP bazlı ceza puanı (RAM map) izlemesi yapılmamaktadır.
   3. [GÜVENLİK RİSKİ] Sabit JWT Secret ve Ortam Değişkenleri (Environment Variables) Kullanılmaması:
      - `JWT_SECRET`, `JWT_PUBLIC_SECRET`, `JWT_BOLGE_SECRET` gibi hassas anahtarlar `server.js` içinde string olarak gömülüdür (hardcoded). `.env` dosyası kullanılmalıdır.
   4. [GÜVENLİK RİSKİ] Dynamic CORS Yapılandırması (Firebase + GCP Entegrasyonu):
      - Firebase Hosting alan adları (`.web.app` ve `.firebaseapp.com`) ile GCP Backend arasında Cross-Origin isteklerine izin verecek dinamik CORS mekanizması kurulmalıdır.
   5. [GERÇEK IP MASKELERİ] Cloudflare Başlık Okuma:
      - İstemci IP adresi alınırken `req.headers['cf-connecting-ip']` öncelikli okunmalıdır.

C. FRONTEND VE DEPLOYMENT KATMANI:
   1. Angular uygulamaları Firebase Hosting üzerinde barındırılacaktır.
   2. `environment.prod.ts` dosyalarında API adresi GCP sunucusunun Cloudflare arkasındaki API adresine (`https://projeniz.duckdns.org/api`) yönlendirilecektir.

DOSYA 8: NGINX KONFİGÜRASYONU (`/etc/nginx/sites-available/default`)
GCP Sunucusunda sadece API Proxy görevini yapacak Nginx konfigürasyonu:

```nginx
# IP Başına İstek Sınırı (Saniyede 10 istek)
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;
# IP Başına Bağlantı Sınırı (Aynı anda maks 20 bağlantı)
limit_conn_zone $binary_remote_addr zone=conn_limit:10m;

server {
    listen 80;
    server_name projeniz.duckdns.org; # Veya GCP backend alan adınız

    # Sadece Cloudflare IP Bloklarına izin ver (Origin IP Gizleme)
    set_real_ip_from 173.245.48.0/20;
    set_real_ip_from 103.21.244.0/22;
    set_real_ip_from 103.22.200.0/22;
    set_real_ip_from 103.31.4.0/22;
    set_real_ip_from 141.101.64.0/12;
    set_real_ip_from 108.162.192.0/12;
    set_real_ip_from 190.93.240.0/20;
    set_real_ip_from 188.114.96.0/20;
    set_real_ip_from 197.234.240.0/22;
    set_real_ip_from 198.41.128.0/17;
    set_real_ip_from 162.158.0.0/15;
    set_real_ip_from 104.16.0.0/13;
    set_real_ip_from 104.24.0.0/14;
    set_real_ip_from 172.64.0.0/13;
    set_real_ip_from 131.0.72.0/22;

    real_ip_header CF-Connecting-IP;

    # Payload (Gövde) Sınırı - 1MB
    client_max_body_size 1M;

    # API Yönlendirmesi (Node.js Backend)
    location / {
        limit_req zone=api_limit burst=20 nodelay;
        limit_conn zone=conn_limit 20;

        # Sınır aşımında bağlantıyı anında kopar (444 No Response)
        error_page 503 = 444;

        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header CF-Connecting-IP $http_cf_connecting_ip;
        proxy_cache_bypass $http_upgrade;
    }
}
```

6. FIREBASE + GCP + CLOUDFLARE + NGINX BİRBİRİNE NASIL BAĞLANIR? (DETAYLI REHBER)
--------------------------------------------------------------------------------

AŞAĞIDAKİ ADIMLAR; BİZZAT KULLANICI TARAFINDAN YÜKLEME VE YAYINLAMA SIRASINDA UYGULANACAKTIR:

ADIM 1: FIREBASE HOSTING KURULUMU VE YAYINLAMA
1. Bilgisayarınızda Firebase CLI yüklü değilse yükleyin ve giriş yapın:
   `npm install -g firebase-tools`
   `firebase login`
2. Ana dizindeki `.firebaserc` dosyasını açın ve `your-firebase-project-id` alanına gerçek Firebase Proje ID'nizi yazın.
3. Firebase konsolunda Hosting bölümüne giderek 3 farklı site (target) ekleyin:
   - `public-app-site` (örn: `projeniz-public.web.app`)
   - `admin-app-site` (örn: `projeniz-admin.web.app`)
   - `bolge-app-site` (örn: `projeniz-bolge.web.app`)
4. Angular frontend uygulamalarını üretim modunda derleyin:
   - `cd public-app && npm run build -- --configuration production`
   - `cd ../admin-app && npm run build -- --configuration production`
   - `cd ../bolge-app && npm run build -- --configuration production`
5. Ana dizine dönüp tüm frontend'leri Firebase'e yayınlayın:
   `firebase deploy --only hosting`

ADIM 2: GCP SUNUCU VE CLOUDFLARE YAPILANDIRMASI
1. DuckDNS veya Cloudflare paneli üzerinden geçici domaininizi (örn: `projeniz.duckdns.org`) GCP Statik IP adresinize yönlendirin (Turuncu Bulut / Proxy Aktif).
2. GCP Firewall ekranında 80 ve 443 portlarını sadece Cloudflare IP bloklarına açın.
3. GCP sunucunuzda Nginx konfigürasyonunu yukarıdaki Nginx şablonu ile güncelleyip `sudo systemctl reload nginx` yapın.

ADIM 3: BACKEND CORT VE .ENV AYARLARI
1. `server/.env` dosyasını açın:
   - `ALLOWED_ORIGINS` satırına Firebase Hosting alan adlarınızı ekleyin:
     `ALLOWED_ORIGINS=https://projeniz-public.web.app,https://projeniz-admin.web.app,https://projeniz-bolge.web.app`
   - `CF_ZONE_ID` ve `CF_API_TOKEN` değerlerine Cloudflare API bilgilerinizi yazın.
2. PM2 ile backend'i başlatın:
   `cd server && pm2 start server.js --name "ekosistem-api"`
   `pm2 save`

ADIM 4: DÜZENLİ CRON TEMİZLİĞİ
1. GCP sunucusunda crontab açın (`crontab -e`) ve ekleyin:
   `*/30 * * * * /usr/bin/node /path/to/server/cf-cleanup.js >> /var/log/cf-cleanup.log 2>&1`
